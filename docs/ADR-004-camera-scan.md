# ADR-004: экран «Сканировать» с живой камерой

Статус: принято 2026-10-19.

## Задача
Игрок наводит камеру на здание и видит карточку здания: название, адрес, тип, факты, организации внутри. Это **не** подтверждение открытия здания: награду по-прежнему даёт только проверенный сценарий `/scan/:buildingId` (ADR-001, сервер).

## Решение
Здание определяется **приблизительно** по GPS, компасу и контурам OSM, без распознавания изображения.

- Живая камера — `getUserMedia` (`src/services/camera/preview.ts`), без нативного плагина. Кадры никуда не отправляются.
- Компас — `DeviceOrientationService` (`src/services/orientation/`): iOS — `webkitCompassHeading` и точность (`webkitCompassAccuracy`), разрешение запрашивается по нажатию; Android — `deviceorientationabsolute`, направление задней камеры по формуле из спецификации W3C. Относительная ориентация (без привязки к северу) не используется. Телефон, лежащий горизонтально, не даёт направления.
- Кандидаты — существующий `osm_buildings_in_bbox` в радиусе 250 м (перезапрос после 100 м), без новой миграции.
- Ранжирование (`src/services/scan/candidates.ts`, чистая функция): лучи в конусе вокруг направления, каждый луч останавливается на первом контуре (ближние здания закрывают дальние). Ширина конуса растёт с ошибкой компаса и GPS. Статусы: `likely` (явный лидер: доля ≥ 0,55 и отрыв ≥ 0,25, GPS ≤ 35 м, компас ≤ 30°), `ambiguous`, `none`, `no_heading`, `inaccurate`. Всё, кроме `likely`, — ручной выбор из списка.
- Стабилизация (`src/services/scan/stabilizer.ts`): карточка переключается на новое здание, только если оно лидирует 800 мс; выбор сбрасывается через 2 с без лидера; ручной выбор держится, пока игрок не отойдёт на 40 м или не включит автоопределение.
- Карточка (`BuildingInfoSheet.vue`) показывает только то, что есть в данных; пустые блоки скрываются или помечаются «Информация пока не добавлена». Расстояние — только при точности GPS ≤ 20 м.

## Организации (миграция 012)
`osm_pois`: именованные узлы OSM (`shop`, `office`, `craft`, `healthcare` — любые; `amenity`/`tourism`/`leisure` — из белого списка). Связь со зданием только доказанная:
- `explicit` — узел является вершиной ровно одного контура здания (Overpass `way(bn)`);
- `inside_footprint` — точка внутри ровно одного контура.
Близость не связывает; при пересекающихся контурах связи нет. Пишет только импорт (service role), игроки читают (RLS). `relink_osm_pois()` пересчитывает связи после повторного импорта зданий.

Замер на Варшавской (2026-10-19, PGlite): 595 организаций, 581 внутри контура, 1 явная, 13 без связи; организации есть у 200 зданий из 1171.

## Ограничения
- GPS в городе ошибается на 5–30 м и больше, компас — на 10–30°: на 50 м это ширина фасада. Поэтому `likely` — «вероятно», а не «распознано».
- ARKit/ARCore не знают зданий. Точное положение дают только ARCore Geospatial (VPS по Street View) и `ARGeoTrackingConfiguration` (ARKit) — покрытие Москвы не подтверждено; это следующий этап после проверки основного сценария на устройствах.
- Не проверено на устройствах: `getUserMedia` в WebView Capacitor (iOS ≥ 14.3, Android), запрос разрешения компаса в WKWebView, совпадение `webkitCompassHeading` с направлением задней камеры при вертикальном телефоне, реальная точность.
